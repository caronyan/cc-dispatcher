# 代码摸底（共用）

在动手之前弄清代码现状：入口和调用链、要改的位置、可以参照的已有实现、相关测试和命令、要遵守的约定。cc-herdr-dispatch-dev（拆任务前）和 cc-herdr-dispatch-fix（问题没有给出位置时）都按这里做。cc-herdr-dispatch-research 的 `code` 线程回答的是调研子问题，用它自己的 investigator.md，不走这里。

下文 `$RD` 是调用方的运行目录，`<用途>` 写调用方要据此做什么（"拆分实现任务""定位并修复下列问题"）。

## 要不要派 Codex

| 情况 | 做法 |
|---|---|
| 同一 base 下已有新鲜的 `survey.md`（父运行或上游产物里的，头部记的 `base_sha` 与当前 HEAD 一致），或方案已经写到文件和行号（例如 cc-herdr-dispatch-research 的 `plan.md`） | 直接用，抽查几处关键位置是否和当前代码一致 |
| 要看的位置你已经知道，并且在小活范围内（3 处以内、约 150 行） | 自己读，只读相关片段 |
| 其他情况：要理清调用链、涉及多个模块、或者说不准会波及哪里 | 派一次只读的 Codex 摸底，见下 |

Codex 不可用时由你自己摸底，不进入降级流程。

## 派发

按下面的提示写成 `$RD/survey-prompt.md`，按 shared/herdr.md 的"派发与回报"派出并等待。范围窄的用 `--effort medium`，否则 `high`：

```bash
python3 $HD run --run $RD --call survey --mode read --effort medium \
  --dir "$ROOT" --schema "$SKILL_DIR/shared/survey.schema.json" --prompt $RD/survey-prompt.md
```

```
你是这个代码仓库的调研工程师，只读代码，不做任何修改。负责人要据你的回报{<用途>}。

<需求>
{方案的目标与范围 / 待修复问题的现象与期望行为；没有方案时写需求原文}
</需求>

<已知线索>
{对话、方案、问题报告里已经提到的文件、模块、接口、报错；没有就写"无"}
</已知线索>

请回答：
1. 要改哪些位置：入口、调用链上的关键函数、数据结构定义，写到 `文件:起始行-结束行`。
2. 有哪些已有实现可以参照（相似功能、同类模块的写法）。
3. 相关测试在哪里，用什么命令跑；没有测试时说明测试框架和放测试的约定位置。
4. 需要遵守的约定和容易踩的坑（错误处理方式、命名、共享文件如路由表/注册表、生成代码）。

规则：
1. 从<已知线索>开始，沿调用关系展开；只为回答上面的问题才扩大范围，不要遍历仓库，不跑测试和构建。
2. 每个位置都要亲自打开看过，行号以当前代码为准；推断写进 note 并注明是推断。
3. 只报告现状和约束，不替负责人设计方案。
4. 答不了的写进 open_questions，说明缺什么信息。
5. 回报按任务文件要求写入回报文件。
```

## 核对与整理

把回报整理成调用方运行目录下的 `survey.md`，头部写一行 `base_sha: <摸底时的 HEAD>`，供下游判断能不能复用。

会左右决策的位置（写进契约、决定怎么拆、决定修在哪一层）你逐一打开那一段核对（`sed -n '<起>,<止>p'`）；与回报不符时以你看到的为准，并在 `survey.md` 里更正。其余线索照录。
