# 验收与修复路由

## 验收步骤

对每张卡，在它的 worktree 里依次完成以下步骤。前面的步骤不通过，就直接给出结论，不必继续往下做。

1. **读回报**：`wait` 输出里 `REPORT=` 指向的回报文件（JSON），检查结果须为 `REPORT_OK`。`status` 是 `blocked` 时直接按搁置处理；`deviations` 和 `open_questions` 逐条记下，后面要处理。
2. **查越界**：`git -C <wt> status --porcelain` 列出所有改动和新增文件，与卡片的"允许改动"逐个比对。越界改动要么撤销，要么在确认合理后补进卡片并记入 `log.md`。`network: true` 的卡还要核对依赖清单和锁文件的变化：新增的依赖只能是"联网理由"中列出的那些，其他依赖一律撤销。
3. **亲自跑验收命令**，以你自己的运行结果为准，不看回报里的 `tests.passed`。只看结果：`<命令> > "$OUT/accept.log" 2>&1; echo EXIT=$?; tail -n 15 "$OUT/accept.log"`（`$OUT` 是 `$RD/agents/T<n>`）。失败时不自己排查原因，把失败的用例和这几行输出写进返工反馈，让 Codex 去查。
4. **读 diff**：先 `git -C <wt> diff --stat` 看全貌（新文件用 `git add -N` 之后再 diff）；锁文件、生成文件、快照只看 stat。
   - 其余改动不到约 300 行：按文件 `git -C <wt> diff -- <文件>` 细看，逐项检查下面五点。
   - 超过约 300 行：你只细看契约接口（对外签名、数据结构、错误约定）和你在卡片里标过风险的那几段，其余几项交给一次**只读复核**（见下文），按它的回报处理。

   检查项：
   - **正确性**：每条验收标准都有代码对应，并且有测试覆盖。
   - **契约**：签名、类型、错误约定与 `contracts.md` 一字不差。
   - **边界**：空值、极值、错误路径、资源释放、并发访问。
   - **测试质量**：测试断言的是行为而不是实现细节；没有被跳过或弱化的测试（`skip`、`only`、删掉的断言）。
   - **风格**：与周围代码一致；没有调试残留、没用到的代码、只用一次的抽象。
5. **处理 `open_questions`**：属于契约问题的，按 SKILL.md 4.5 的契约修正处理。你能查清或能自己定的直接处理；需要用户回答或拍板的（业务规则、期望行为、取舍偏好），按 shared/herdr.md「待决项」写成 `question` 或 `decision`（`card` 填这张卡），不卡住的话这张卡照常往下走。

## 结论与路由

| 结论 | 条件 | 动作 |
|---|---|---|
| 通过 | 1-5 全部满足 | 进入 4.6，提交并合入集成分支 |
| 小修 | 问题集中、修法明确，并且在小活范围内：一个文件、约 20 行以内 | 你直接改，重跑验收命令，在 `log.md` 记"Claude 小修：<内容>" |
| 返工 | 超出小修范围：问题分散在多个文件、需要重新设计某段逻辑、测试缺失、或者原因还要排查 | `hd_dispatch.py send` 发给原来的子 agent，提示格式见下 |
| 搁置 | 返工满 3 轮、`blocked`、契约本身有错 | 停下，交给用户 |

如果某次小修改动了核心逻辑（不只是改名、补判空、调整格式），就对你的改动做一次只读复核，弥补自己审自己的盲区。

## 只读复核

用于大 diff 的验收（第 4 步）和核心逻辑的小修。开新调用，不发给实现者，避免沿用它的思路。复核调用不是卡片，不写进 `state.json.tasks`；结论记在被复核的卡的 `checks` 里（如 `{"r1": "ISSUES"}`）和 `log.md`。只读模式改不了 git 索引，派发前先由你 `git -C "$WT_ROOT/T<n>" add -N .`，让新文件出现在 `git diff` 里：

```bash
python3 $HD run --run $RD --call T<n>-check-r<k> --mode read --effort medium \
  --dir "$WT_ROOT/T<n>" --schema "$SKILL_DIR/references/check.schema.json" --prompt $RD/T<n>-check-r<k>.md
```

check-prompt：

```
你是验收复核者，只读不改。对象是当前 worktree 相对 <集成分支提交> 的改动（git diff <sha>）。
任务卡：<卡片全文>
契约：<contracts.md 中与本卡相关的部分>
逐项检查：正确性（每条验收标准都有代码和测试对应）、契约（签名/类型/错误约定一字不差）、
边界（空值、极值、错误路径、资源释放、并发）、测试质量（断言行为而非实现，没有 skip/only/删断言）、
风格（与周围一致，无调试残留和无用代码）。<需要特别关注的点>
只读改动涉及的文件和它们直接调用的代码，不遍历仓库，不跑全量测试。每条问题写位置、问题、证据和期望的修法。
```

复核回报的每条 `must` 级问题，你打开那一段确认（只读那几行）；确认成立的写进返工反馈或作为小修处理，不成立的在 `log.md` 记下理由。`LGTM` 且你看过的接口部分没有问题，第 4 步算通过。

## 返工提示（`hd_dispatch.py send --call T<n>`）

```
架构师验收未通过，第 <k> 轮反馈如下。请在当前 worktree 中修改，规则与首轮相同。

必须修复：
1. [<文件:行>] <问题> —— <期望的行为或修法方向>
2. ...

建议改进（可选）：
- ...

修完后重新运行验收命令：<命令>
回报按任务文件要求写入回报文件。
```

每条反馈都要写清楚**位置、问题、期望**三要素。"再优化一下"这类反馈会让返工原地打转。
